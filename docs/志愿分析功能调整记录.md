# 志愿分析功能调整记录

更新时间：2026-05-07

## 背景

围绕资料库分类「报考志愿」，项目新增了一个正式的 **AI 高考志愿分析建议工具**。功能目标不是简单聊天，而是基于用户成绩信息、院校库、专业库、院校专业关系、历年录取分数/位次和报考志愿知识库，生成可追溯的冲稳保建议报告。

- 将原先 MVP/分阶段口径改为一步到位的正式交付范围。
- 更新需求文档，补充 AI 志愿分析工具调用链路、输出要求和数据要求。

### 2. 数据模型

在 `backend/prisma/schema.prisma` 中新增/扩展：

- `AdmissionScore`：历年录取分数/位次数据。
- `Major`：专业基础库。
- `UniversityMajor`：院校开设专业关系表。
- `VolunteerReport`：用户 AI 志愿分析报告。
- `AdmissionScore.universityMajorId`：录取数据可选关联到具体院校专业。
- `User.volunteerReports`、`University.admissionScores`、`University.universityMajors` 等关系字段。

当前核心关系可以按运营视角理解为 4 层：

```text
1. Major 专业库
   只描述专业本身，例如：计算机科学与技术、法学、临床医学。

2. UniversityMajor 院校开设专业
   连接 University 和 Major，表示某所学校开设某个专业。
   示例：北京大学 + 法学、清华大学 + 计算机科学与技术。

3. AdmissionScore 录取分数线
   描述某省、某年、某科类下，院校或专业组的最低分/最低位次。
   它优先关联 University；如果后续有专业级录取数据，也可以关联 UniversityMajor。

4. VolunteerReport AI 志愿报告
   保存用户输入、AI 分析结果、Markdown 报告和扣点记录。

User
  └─ VolunteerReport 志愿分析报告
```

后台管理入口按实际操作场景拆分：

```text
专业库：独立页面，维护专业本身。
院校库：独立页面，每所院校通过“查看专业及历史录取线”查看该校开设专业和近三年录取线。
录取分数线：独立页面，维护省份/年份/科类下的分数和位次。
志愿报告：独立页面，查看用户生成的 AI 报告。
```

### 4. 志愿分析服务

`volunteer-analysis.service.ts` 已实现：

- 用户输入校验。
- 按深度分析扣除 18 咨询点数。
- 检索录取分数/位次数据。
- 根据位次或分差划分冲刺、稳妥、保底。
- 检索「报考志愿」知识库。
- 检索专业库和院校专业关系。
- 调用 DeepSeek 生成报告；AI 不可用时使用本地兜底报告。
- 生成失败自动退还点数。
- 保存 `VolunteerReport`。
